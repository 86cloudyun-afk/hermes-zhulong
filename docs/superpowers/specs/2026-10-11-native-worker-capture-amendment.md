# Prospective native worker capture amendment

The original six-cell v0.11 batch remains unknown=1/unrun=5. Its actual workers had a static preflight boot label because the pinned gateway's YAML bridge overwrote launch environment arguments. No original endpoint, receipt, budget or denominator may be rewritten. Any later paid batch needs a distinct preregistration after this implementation and independent review.

Immutable configuration omits only the launch-owned `docker_extra_args` field (an empty list would overwrite it). The protected generator still supplies every existing Docker hard floor, deployment label and actual service-boot label. Freeze records static config and the complete hashed launch-argument declaration separately, with narrow typed deployment/boot substitution. Single-profile gateway restrictions remain mandatory. Pinned bridge/default behavior and effective actual startup must be tested; no pinned host patch or acceptance of preflight as current boot.

Paired mode installs a protected host-only Docker creation observer using the pinned supported `HERMES_DOCKER_BINARY` override. Its code, scope, real Docker binary and installed wrapper are hashed. On each main worker creation it delegates to the real daemon, inspects the actual returned container, checks current service boot, owner process, session, image and full boundary, and durably captures the observation before returning the container ID to Hermes. Records are private and never mounted into the worker. Probe creation is separate and cannot qualify a main run. Multiple containers are captured separately; duplicate/replaced/stale/foreign identities reject.

The paired protected foreground runner adds its actual hostname to the exact structured receipt. Qualification joins that receipt to the daemon-inspected hostname/container and immutable native Runs/session mapping; a supplied hostname/boolean/hash alone is never authority. Existing generic/default and certified helper behavior remains unchanged unless this paired option is explicitly selected.

Creation, inspection and journal work consume the same persisted 180-second endpoint. Cleanup retains its independently frozen 120-second grace. Missing/late capture remains unknown and stops future allocations. The observer does not create extra model work, poll faster as proof, rescue a prior endpoint or infer provider billing/model versions. Existing cohort implementation and running observer are outside scope.

Tests must exercise the pinned bridge's key-presence/default behavior, unchanged hard floors, actual container/session/boot binding, sequential workers and exact foreground correlation, replacement/foreign/stale/probe rejection, capture-before-use ordering, deadline overrun and existing regressions. Local mocked daemon boundaries are lifecycle tests; actual Docker/startup evidence is separately identified. Root owns new paid preregistration and runs after review.
