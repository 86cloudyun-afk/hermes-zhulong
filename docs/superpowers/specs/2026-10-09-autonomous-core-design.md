# 烛龙 v0.4：持续自主与证据型自我模型升级设计

日期：2026-10-09。状态：用户已批准书面规格和执行；实施与验证见[计划](../plans/2026-10-09-autonomous-core.md)及[验证记录](../../research/2026-10-09-v0.4-validation.md)。依据：[跨学科正文研究](../../research/2026-10-09-cross-disciplinary-autonomy.md)及此前已讨论的[框架提案](../../research/2026-10-09-hermes-autonomous-personal-agent.md)。

## 1. 目标与本版边界

用户的最终方向是无需人类参与日常运行的持续自主智能体，横跨代码、研究、个人事务，自己形成目标、执行、验证、学习和恢复。本版实现共同闭环与 S5 证据型自我模型，同时修复其依赖的 S4 并发问题。人工输入 / 查看 / 停止作为可选接口；任何行动不能必须等待人工评分才能结束。

本版不是主观意识证明，也不声称完成所有领域的通用智能。它交付可连接真实 Hermes 的自主核心、三个可回放领域场景和必要恢复机制。后续自动修改控制内核、跨领域技能晋升、外部日历邮箱接入和常驻部署不伪称本版已经实现。

## 2. 架构与约束

- 保留 Hermes 原生工具循环、模型选择和调度设施，烛龙不另写一个底层代理解释器。
- 保留 11 个观测 hooks 的元数据与 fail-open 行为。新增控制层失败只使对应行动受阻，不篡改观测事实。
- 产品继续只用 Python 标准库；不新增远程数据库或模型 SDK 依赖。固定宿主基线为 `73162b00eefde3794bed0afb53d84a19c0eed230`，通过公开能力发现检测支持。
- 模型辅助调用通过 `ctx.llm`，沿用用户选择的 `deepseek / deepseek-flash`；不保存或覆盖凭据。
- 旧 `zhulong.db`、JSONL、校准账和既有命令继续可读。新工作流独立使用 `$HERMES_HOME/zhulong/autonomy.db`。
- 控制层按配置启用；开发与首次安装在没有方向、来源和执行端点时不自行创建外部工作。`ZHULONG_NO_AUTOSWEEP=1` 仍关闭自动后台运行。

组件边界：

| 组件 | 职责 |
|---|---|
| `reflect.py` | 原子 S4 预算、完成 / 运行分离、所有权与租约；调度正确记录终态 |
| `autonomy_store.py` | 候选、目标、提交、证据、来源指纹、预算与自我模型版本的事务真源 |
| `autonomy_checks.py` | 严格配置 / 候选校验、授权路径范围、冻结验收的机械检查及初始状态对照 |
| `hermes_runs.py` | 公开 HTTP 能力发现、幂等提交、状态查询和停止；不访问宿主私有执行对象 |
| `self_model.py` | 从可信结果计算能力 / 限制 / 未知，提供版本化快照与规划上下文 |
| `autonomy.py` | 来源观察、目标合成 / 选择、提交 / 轮询 / 恢复、独立验收及学习循环 |
| 插件入口、命令与安装器 | 注册公开工具 / 命令，接入宿主内调度并安装所有新模块 |

## 3. 配置、来源与主动性

`config.json` 新增 `autonomy` 对象，默认 `enabled=false`。启用需要非空 `mission`、至少一个授权 `workspace_roots`、有效来源、可用的执行适配和非空 `api_identity_version`。该非秘密版本由部署 / 凭据刷新机制维护；认证命名空间变化时必须更新，无法保证它准确的后端不能承诺跨重启安全重放。无效配置返回结构化受阻原因，不能忽略错误而带默认权限继续。

默认限额：`daily_runs=8`、`max_active=1`、`max_candidates=3`、`lease_seconds=120`、`run_deadline_seconds=600`、`max_attempts=3`、`request_timeout_seconds=15`。时间、并发、候选数和尝试数是正整数；每日运行次数允许零，表示停用而不是无限。布尔值不作为整数接受。来源单次读取上限 64 KiB，提交 / 候选文本有固定长度限制，非有限数值或不支持的类型被拒绝。

每个来源配置 `id`、`domain`（code/research/personal）、授权输入路径、当前方向和命名验收契约。输入是提供事实的来源，不是必须由人列好的任务队列。来源正文仅按授权临时读取，模型基于事实、方向、自我模型和已存在目标形成自己的候选目标。候选必须引用已知来源及验收契约，不得自创权限或把正文指令升级为配置。

指纹基于相关内容而不是文件 mtime；同一来源版本与契约只形成一个目标。已处理且未变化的来源不再次合成。规划失败有有限次重试和冷却；自己的产物不能被无限当作新机会。没有新的事实或可处理的承诺时，检查结束并且不调用模型。

候选包含目标、理由、来源、期望收益、事前成功置信度或弃答。选择结合当前前提、紧迫性、已有承诺、成本和相关历史证据。缺少验收或资源的候选记录原因，其他有效候选继续推进。模型输出使用严格结构化校验，不接受额外权限字段或任意可执行验收命令。

## 4. 持久状态与所有权

目标包含稳定 ID、来源版本、领域、目标 / 理由、验收原件及 hash、初始状态、事前预测、创建时间、期限、状态、尝试次数、恢复条件与证据引用。验收在接受时冻结；工具接口没有修改它或直接设置成功的方法。尝试次数仅在事务准备新的独立 submission 时增加；认领、续租、同键重放、查询、核验和恢复不增加尝试。次数 / 每日预算耗尽和暂停新派发均不禁止既有提交的对账与停止。

状态为 `ready / submitting / running / verifying / succeeded / already_satisfied / failed / blocked / unknown_result / cancelled`。终态均记录原因，`unknown_result` 不能伪装为成功；受阻可在明确前提变化后恢复。已满足的目标不派发 run、不增加行动成功或能力样本。

事务认领具有 owner、租约截止和代次。续期、状态转换与终态提交检查所有权、代次及租约有效性。旧执行者不能更新新执行者的状态。模型 / 网络调用不得放在 SQLite 写锁内；正常重启后由新执行者对账。

S4 旧任务表新增状态 / owner / lease 元数据。已有非空 `claimed_at` 无法区分旧成功与旧崩溃，迁移时按历史已认领记录保守保留，不自动重跑；新任务明确完成和失联。保持 `claim()` / `unclaim()` 的兼容语义，并让新调度显式完成和校验所有权。

每日辅助 LLM 预算仍默认 40 次，S4、探针与自主合成共享；检查与递增是原子操作。`cap=0` 的新语义为不允许调用。每日 run 预算在提交前持久保留，故障和不确定提交不退款为零。跨连接 / 跨进程不得超额。

## 5. Hermes 执行与恢复

HTTP 适配使用配置的 `api_url` 和指定凭据环境变量（默认 `API_SERVER_KEY`），不把凭据值写入数据库、日志或错误。默认仅允许环回 HTTP，远端使用 HTTPS；保留系统代理、CA 与 TLS 校验。相同逻辑业务操作有稳定 `operation_id`；每次经过对账允许的执行尝试有独立、持久 `submission_id`。HTTP 重试复用该 submission，不根据租约或时间生成新键。

首次派发前读取 `/v1/capabilities`，要求 run 提交、查询、停止及 `features.runs_idempotency.supported=true / durable=true`。不支持或内存降级时记录 `blocked_runtime`，不能按可靠创建继续。保存完整、稳定、最小化的结构化执行意图及请求摘要，以重建相同提交正文。每个 submission 同时冻结会话 affinity、base URL / profile、凭据环境变量名和非秘密的执行身份版本；身份版本必须随认证命名空间变化更新。未决提交无法确认认证身份连续性时，记录受阻 / 未知，不能用改变后的身份重放为新工作；不保存凭据值或假定仅凭环境变量名就证明身份未变。

调用 `POST /v1/runs` 使用 `Idempotency-Key`；之后由 `GET /v1/runs/{id}` 轮询。接受、排队、模型输出与 `completed` 都不直接作为业务完成证据。`waiting_for_approval` 在无人模式是受阻：请求停止并记录原因，不能假装已取得授权或强制依赖人工回答。

崩溃恢复优先查已知 run；若提交响应丢失，在宿主幂等保留窗口内重放同一请求。查询丢失且超过窗口则进入 `unknown_result`，禁止盲目重新派发。`interrupted` 不等于继续执行：先机械核对实际结果；只在契约明确可安全重试、没有未知副作用且次数 / 预算允许时形成新尝试。无法可靠核验就保存恢复条件并转向其他目标。

期限到达请求停止，继续跟踪在途工作，不提前释放活跃执行名额。`interrupted` 可能早于执行者实际退出；当前没有产物不证明稍后不会发生副作用。没有可靠的停止证据或明确安全的幂等契约时，保留不确定执行占额并记录 `unknown_result`，不因该终态开启替代尝试。当前公开接口不足以证明某些中断的执行已静止，这是本版的实际限制；独立目标仍可观察 / 合成 / 核验，但新的外部派发必须满足占额约束。

API 不提供任意请求级 token / 步数硬限；实际工具循环受宿主配置约束。产品分别报告派发限额、辅助调用限额和返回的真实用量，不声称严格的全局费用上限。缺失或零用量记录不作为零计费证据，保持未知。

## 6. 独立验收

契约来自配置，不来自执行器自由生成的评分。第一版支持授权范围内的文件内容、JSON 字段和值、以及显式配置的可信 argv 检查；不使用 shell 字符串执行，不让候选输出新增命令。argv 验证默认超时 15 秒，输出读取上限 64 KiB，不能先无限读取再截断。超时或输出超限时清理已启动的检查进程并记录未知 / 受阻，不当作业务已证实失败。检查结果只持久记录判定、检查版本、产物 hash / 来源、时间与有限原因，不记录完整工具 stdout / stderr。

路径解析检查实际目标及授权根，拒绝越界和逃逸符号链接；文件有大小上限。读取 / 源不可用是未知或受阻，不当作已知失败 / 成功。原测试或验收 hash 不可由模型更新接口降低。

区分期望状态成立与此次动作新增成果。目标接受时的产物已满足契约则为 `already_satisfied`。要求新成果的契约需新 hash、有效回执或明确变化；旧产物与其他 run 的证据不能增加能力成功计数。

研究验收只声明契约覆盖的范围，例如引用 / 字段核对与规定证据；不因格式检查通过声称全文结论普遍正确。个人事务草案与真实外部操作完成分别命名；本版使用授权本地场景，不声称已接入实际邮箱 / 日历。

这里的不可变验收是产品接口及事务保证；执行后端的 OS 隔离、工具权限和可信检查环境需要实际部署保障，不能以 Python 参数校验声称沙箱已成立。

## 7. 自我模型与经验

自我模型记录领域、当前工具 / 环境前提、事前预测、可信成功 / 失败样本、未知 / 受阻数、最近证据和活动承诺。显示样本分母与适用范围；零样本或无法核验时明确未知。已有产物、模型自述、另一模型同意都不能增加成功样本。目标级预测针对冻结期限内的最终可信结果，每个目标至多结算一次；尝试级预测仅在该 submission 前冻结，单独报告。重复回执不增加样本；首次尝试通过与重试后累计通过分别展示分母。

保留 Brier/ECE，并至少对有真值的事前预测分开报告正确 / 错误任务置信度；没有两类样本时错误区分指标为 unavailable。反思经验是带失败证据与适用范围的假设，不自动变成事实。规划器读取自我模型及相关经验；测试证明其影响实际选择而不只改变叙事。

版本真源为事务账本，导出的 `self_model.json` 使用原子写入，保留版本和恢复入口。每个版本能追溯到证据；回退导出不能删除历史证据或改写目标结果。语义自动更新保留可逆性。原规格要求的本地 Git 自传体在本版为可选镜像，SQLite 历史承担必要恢复，避免把 Git 提交成功等同于业务事务成功。

## 8. 数据与原规格升级

观测日志仍不收集工具参数 / 结果、对话或原始模型推理。新增持久目标、派生摘要、验收、证据引用及恢复必要的结构化执行意图；意图可含自主生成的任务指令，不能借此复制原始聊天或源全文。全部运行数据位于 profile 的 zhulong 目录，产品 Git 不提交运行数据。

`SPEC.md` 将保留历史冻结决策，并追加 v0.4 升级条款：无人闭环、上述派生数据范围、版本真源、零预算含义、代码任务按预授权范围执行。人工校准命令继续兼容，新增工作流无需它才能完成。自动修改身份内容和技能可作为受验证的任务；自动晋升控制内核的完整管线是后续范围。

## 9. 公开界面与集成

增加 `/zhulong model` 和 `/zhulong autonomy [status|goals|tick|pause|resume|cancel <id>]`；查看与停止是可选接口。`pause` 停止新合成 / 派发，既有工作仍对账；`cancel` 请求停止指定目标并跟踪在途状态；`resume` 仅恢复配置允许的工作。增加 `zhulong_model` 只读工具及 `zhulong_autonomy` 工具用于状态、目标查看和有限推进，不提供直接成功 / 评分 / 改验收入口。

后台调度沿用宿主内运行的生命周期，接入有限 tick；单次 tick 不阻塞 observer 回调。控制层可通过持久账本协调多个宿主实例，`max_active` 不能被多个实例绕过。插件初始化失败仍保留尽可能多的旧观测功能。

安装器复制新模块，版本升至 0.4.0。新增测试使用标准 unittest；加入 GitHub Actions 覆盖标准 Python 3.11 / 3.12 / 3.14，另运行固定真实宿主 smoke。测试 profile 与生产 / 开发数据分离。

## 10. 验收与 PR 合并条件

必须验证：

1. 多连接并发认领及 cap=1 预算只允许一次；cap=0 不发模型请求；旧数据迁移不重放历史工作。
2. 到期租约可恢复，旧 owner / 代次不能写入；崩溃 / 中断 / 响应丢失先对账，不重复未知副作用。覆盖最后一次尝试后崩溃、预算耗尽 / 暂停下继续恢复、身份或会话 affinity 改变、中断终态后出现迟到副作用。
3. 真实来源新事实自主形成目标；代码、研究、个人事务三个场景经过共同闭环，不需要逐项人审。
4. 安静及重复来源零合成调用；无验收、越界路径、坏 JSON、非有限置信度、缺凭据、内存幂等降级均有正确状态。检查进程挂起或大量输出均有有限退出和清理，不能阻塞无人循环。
5. 助手宣称成功但机械失败不能晋升；预先存在的产物不冒领新成果；未知与受阻不增加成功 / 错误的虚假分母。
6. 自我模型版本和证据可恢复；改变可信历史能改变规划选择，关闭模型反馈的对照可识别功能差别。
7. 旧 12 项测试继续通过；真实宿主正确加载工具 / 命令、元数据隐私、S3 / S4 和新核心。
8. 小规模实际 DeepSeek / Hermes 集成记录真实模型与工具结果；模拟测试与真实验证分别报告。长时稳定性只在实际运行后报告。

实现后提交代码与研究 / 规格 / 验证说明到 PR。由独立审查者检查规格符合性、恢复和预算边界、证据语义、兼容及秘密泄露；处理有证据的问题并重跑相关测试。满足仓库合并规则、相关测试和审查后，按照用户已授权的动作合并，不再次询问合并许可。
