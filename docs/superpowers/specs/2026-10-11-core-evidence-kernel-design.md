# Core evidence kernel, v0.11

Baseline: `705a3f7aabfd89f42ea362da4ee03f5c3d856ecc`. Standing user authorization covers research, implementation, testing, independent review, PR and merge. This specification is the next finite engineering batch in an ongoing research program. Larger available budgets do not authorize changing scientific endpoints after outcomes are known.

## Problem and scope

The current cognition forecast duplicates its own immediate selection order. Runtime refinement audits a useful but restricted protocol; it cannot certify arbitrary generated Python. The causal ledger validates receipts supplied by a caller but does not itself execute paired native deployments. None of these establishes subjective consciousness or general long-term usefulness.

This batch adds three connected capabilities: prospective attention evidence and optional focus control; a total, effect-free ticket language with all-input certificates and actual protected execution; and a real native paired adapter with durable elapsed-time observations. Existing defaults, native guardian floors, authorized input, recovery and cancellation remain usable.

## A. Prospective attention

An optional `attention_mode=off|adaptive|constant|permuted` defaults to off. All settings are strictly validated and included in mechanism/policy scope. Freeze metadata-only predictions at observation t, including every configured source, then evaluate against later independently observed availability/revision/input/facts at t+1 before learning or current selection. Current selection equality is a separate schedule diagnostic. Empty eligibility still settles the preceding forecast and allocates the next one. Scope change, late observation, unavailable input and absent future observation remain explicit denominator categories.

Append-only forecast/outcome tables forbid UPDATE, DELETE and replacement collisions. Predictions contain canonical hashes, immutable prior outcome cutoffs, current focus and waiting-state hashes, horizon and finite probabilities; no new raw facts or prompts. Brier scores include only on-time observed binary freshness targets and print scored/allocated/excluded counts. Summary cannot invent or settle an observation. Restart must preserve pending predictions and avoid duplicate learning.

Adaptive ranking uses prior settled freshness frequencies, actual prior focus, switching penalty and waiting state. Constant and deterministic permutation controls share all other rules. Oldest overdue continuously eligible sources receive precedence. State the exact finite fairness bound for a fixed source population; arbitrary churn has no such guarantee. Claims concern functional metadata attention, not complete AST/GWT or provider hidden activations.

## B. Restricted total correctness

Provide a strict typed JSON AST for `ticket_priority_v1`: bounded mathematical integer literals, severity, age, blocked, addition, constant multiplication, minimum, uniform conditionals, comparisons, and fixed priority strings. Score cannot refer to itself. No arbitrary Python, calls, IO, dynamic fields, recursion or candidate list wrapper.

An untrusted certificate partitions all ten severity/blocked pairs over integer ages 0..87600. Verify exact gap-free and overlap-free coverage of all 876,010 numeric rows. Derive affine expressions and uniform guards independently; compare score and priority to a separate trusted business relation. Reject witness, type, threshold, branch, domain and resource-limit tampering. Accept structurally different equivalent ASTs. Public execution always rechecks canonical program/certificate bytes and uses that exact AST, a fixed domain validator and list wrapper preserving all IDs and sorting by (-score,id). Checker soundness is a reviewed mathematical argument, not a mechanically formalized theorem.

An optional trusted `program_bundle` is accepted only on ticket `json_reference` v1 contracts. Its canonical serialized size is at most 6000 bytes; parser/AST nesting must fit the existing request/input bounds. The pure checker may permit a larger bounded certificate, but that does not authorize truncating or bypassing the 16 KiB execution-intent limit. Bind normalized program/certificate and derived semantics/spec/domain/checker hashes to the frozen contract, source/input/rule and execution request. Admission checks the exact bundle against the frozen goal in the existing write transaction, before reservation/submission. The pre-created intent binds the goal; the generated submission ID binds through the immutable submission row and its admitted request, rather than an invented pre-known ID. A report or Python object cannot authorize a forged bundle.

The protected native runner loads the exact supplied bundle from a deployment-manifest-bound read-only control file, rechecks it through the protected interpreter and consumes the canonical frozen input. It emits an execution hash receipt and actual result. Independently audit runner/kernel/bundle/input/output hashes and the native foreground transcript; a worker-written receipt alone is insufficient. Retain independent business artifact verification. Failure cannot turn into arbitrary Python fallback or weaken cancellation/recovery.

## C. Real trials and elapsed follow-up

Freeze all six allocations for the existing three fixture families before paid work: statistical control `planner_masked`, treatment `planner_visible`, estimand visible minus masked qualified success. Both arms use cognition enabled, capacity 1, adaptive selection, TTL 300, attention off, learning disabled, identical monitoring/budgets/tools/host/model/image. The sole declared intervention is `mask_consumer=planner|null`. This small trial supports integration only, including ties and failures.

The adapter takes explicit arm policy; no global monkeypatch. It derives business/native/settlement/cleanup/arm receipts from retained deployment artifacts and transcripts, using independently authored expected outputs. Freeze actual hashes and a narrow declared role normalization for allocation paths, profile/session/deployment identifiers and loopback ports; verify their actual bindings before comparison. Do not normalize provider/model/input/rule/image/control code or permission differences. Provider alias and underlying model identity are separate facts.

The one 180-second endpoint starts immediately before unpause/discovery, using a persisted UTC origin and one monotonic deadline shared by all phases. A separately declared bounded cleanup grace cannot rescue a late endpoint. Append launch intent before external launch. Ambiguous launches on resume authorize reconciliation, never another paid attempt. Unknown settlement or cleanup stops further launches. Full provider usage/billing unknowns stay unknown.

A separate append-only cohort protocol records actual 0/6/24/48/72-hour observation windows, hash-chain events, claims, launch ambiguity, owned resources and recovery dispositions. Elapsed follow-up, continuous liveness and causal long-term benefit are separate endpoints. Check wall-clock and boot/monotonic continuity; retain late, missed, unknown and not-due cells in the original denominator. Fake-clock lifecycle tests never count as a real soak. Observation-only cohorts must not imply continuous service or usefulness.

## Frozen evaluation and falsifiers

Freeze a provider-free actual Controller attention study before running: fixed stable/volatile/source-loss/restart/empty/horizon scenarios, identical starting ledgers, constant/permutation controls, all allocated forecast counts, actual planner deliveries and zero provider calls. Any future-data leakage, dropped prediction, nonchanging controller under discriminating model ablation, lost fairness or protected admission bypass rejects its corresponding claim. A null adaptive advantage stays null.

For certificates, test independent malformed covers and nonidentical equivalent ASTs; cross-check every numeric row against the existing independent reference as supplemental implementation verification, plus list ID/tie/domain behavior and native binding. This exhaustive check is distinct from the interval certificate argument.

For native trials freeze input/oracle/control hashes, schedule, deadline/cleanup semantics, all cells and stop conditions. Do not pool prior pilots. Existing fixed-N analysis and small-N restrictions remain; no post-outcome estimator switch. Actual 24/72h results require time to elapse. A pending cohort is delivered as pending, never completed.

## Trust and exclusions

Trusted: strict parser, custom proof checker/interpreter, immutable SQLite/code/config controls, input validator/list wrapper, independent local qualifier/oracle, host/runtime/clock observation and protected execution bridge. Audits of hashes establish provenance rather than external truth. Native context delivery proves exposure rather than model comprehension. Arbitrary program correctness, subjective experience, all future execution paths, undisclosed provider retries/billing, universal process quiescence and general causal long-term benefit are outside this batch's proof scope.
