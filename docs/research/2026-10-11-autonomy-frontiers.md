# 完整执行、失败根因、因果提升、意识与正确性：下一阶段研究

日期：2026-10-11。产品基线：`deffc94e0c30ef3b20481ff6aaf9af5687371ef5`（v0.8）。本轮交付研究正文、离线复现实验和下一阶段验收协议；没有升级产品版本，也没有进行新的付费模型实验。

用户希望 Hermes 自行发现有价值的工作，持续完成、诊断和改善自己的任务，长期减少人工参与。五个目标需要不同证据：完成任务的收据、诊断因果的干预、评价提升的随机对照、功能自我监控的行为测量，以及受限系统的正确性论证。一个指标不能替另外四个指标背书。

## 1. 研究结论与工程顺序

## 2. 可复现结果与实际范围

复现代码和命令见 [实验说明](experiments/autonomy_frontiers/README.md)。每个脚本把输出写到调用者指定的目录，产品和实际 profile 不被改动。研究脚本只使用标准库与仓库已有夹具。

### 2.1 执行：账本正确不等于外部效果只有一次

实际 `Ledger` 拒绝旧租约代次的 admission 写入，并接受新代次；独立的未接入 fencing 的模拟效果端仍会执行两个动作。这个模拟结果展示协议缺口，**没有观察到真实网关重复动作**。

另一个独立 SQLite 适配器演示将效果与稳定 operation key、请求 hash 和 fencing 检查放进同一事务：旧 token 被拒绝；提交后丢回复再重放返回原结果；相同 key 改意图冲突；效果数为 1。这是协议示例，尚未成为产品连接器，也不模拟任意远程服务。

独立审查发现原示例的两个 SELECT 发生在隐式写事务之前；已通过双连接受控时序复现，并加入显式 `BEGIN IMMEDIATE`。补充探针证实 fence 读取在事务内、第二连接更新被阻塞，效果提交后提高 fence 再拒绝旧 token。原反例、修复结果及研究脚本 hash 均保留在 [审查闭环](2026-10-11-frontiers-review.md)；这仅验证该受控协议时序。

完整执行须分开判断：目标验收是否成立、每个动作是否有可信回执、结果是否已静止、遗漏步骤是否可恢复。任意外部服务不可查询、永久中断或需求本身不可满足时，系统应保留有原因的 blocked/unknown/failed；“不造假地终止”和“完成有用任务”分别统计。

### 2.2 已定位的主验收解析差距

当前 `Verifier.json_equals` 用 `json.loads`，技能评测器用 `strict_json`。主验收在期望 `sum=6` 时接受 `{"sum":0,"sum":6}`，而严格解析拒绝重复键；键反序则主验收失败。主验收还接受目标字段正确、无关字段含 `NaN`、`Infinity` 或溢出指数的文档。

控制样本表明 `true` 与 `1`、`6` 与 `6.0` 都不会混同，目标字段本身为非有限数时也没有通过。问题是整份文档的解析语义不一致，**不是类型混淆，也不是已确定的历史生产失败根因**。本轮记录最小复现，产品修复列为 R0。

### 2.3 诊断：联合故障与最小输入

可信夹具对整数数组求和。故障 A 丢负数，故障 B 丢末项。三个预定输入上下文、四个因子组合、每格三次，共 36 次新鲜离线 Python 运行。主上下文 `[3,-2,4]` 下，单独 A、单独 B 和同时 A+B 都失败；同时修复才通过。某因子被输入屏蔽时，该因子没有影响。

对 A+B 的缩减得到 `[4]`，删除任一剩余元素不再复现，满足该失败谓词的 1-minimal 条件。但它完全隐藏了负数故障 A。因此“最小复现”“可疑度最高”“修一处后仍失败”都不能直接等同于完整原因集合。实验只验证这些已知注入故障，不诊断模型内部机制。

### 2.4 提升：统计演示不产生模型提升证据

固定种子、六个难度/领域层、384 个模拟任务对：基线 218 次成功，模拟 treatment 268 次成功。效应、配对检验、分层 bootstrap、保守固定样本界和四个篡改/缺失负例均可复算。生成器预先包含有益机制，故数字是**统计管线演示**；没有实际 Hermes 或 DeepSeek 因果提升结论。

对真实试验，任务输入相同不代表两组资格相同：技能/经验绑定 source、完整 contract hash 和执行身份；换 profile、端口、结果路径或期望值会改变范围。现有 `learning_enabled` 同时控制经验和技能，也允许生成与状态改变，不能直接充当“只关闭某一机制”的随机对照。先解决这些干预定义问题，再花模型预算做正式试验。

现有 sum 契约期望值固定为 6，并向执行者提供该契约。即使换成未见过、总和仍为 6 的输入，也可能直接写答案通过。因此该试验最多测契约成功；要声称真正计算或执行技能，需额外独立执行证据与动态参考函数的可信评测任务。不能悄悄改现有固定期望值，或把公开答案说成隐藏 oracle。

### 2.5 元认知：可计算性不是识别质量

实际调用 `self_model._metrics`，每组只有四条人工合成观测。正确排序、反向排序、恒报 0.5 的 `error_discrimination` 都是 `available`；研究脚本计算的配对 AUROC2 分别为 1、0、0.5，Brier 分别约为 0.025、0.725、0.25。该字段现有含义是两类样本存在，不能读作质量指标。

这不是新的产品 AUROC 功能，也不是当前模型的元认知成绩。下一阶段需同时测校准、错误排序、任务难度与元认知对控制的实际影响；meta-d′/d′ 等指标需要适合的数据和建模假设，不应由四条二元合成记录直接估计。

### 2.6 正确性：实际代码的有限枚举

通过既有 `ReplayTests` 夹具调用实际 `SkillStore.finish` 与 SQLite，枚举 12 个布尔守卫的 4096 个组合。一个全部满足的组合发布；4095 个组合拒绝且候选保持未发布；另六个图像、用例、计数和精确类型负例也拒绝。unknown 后保留同代码、同 token、同 evaluation digest，恢复时租约代次增长。

只替换 Docker case runner/cleanup；没有在此实验中认证实际容器清理、并发、数据库故障或任意候选程序。直接 `SkillStore.finish` 在 paused 时仍可接收有效报告，支持入口 `SkillLearner.tick` 在 paused 时不调用模型/预算/评测且保留候选。这说明暂停由外层 gate 承担，**尚未证明暂停与发布的原子排序**；不能把该观察直接写成支持入口存在已复现竞态。

这些是有限输入分区的穷举测试。要成为形式验证，还需要明确状态模型、不变量、环境假设、证明或模型检查，以及模型到实现的对应关系。

## 3. 后续工程与研究验收协议

### R0：统一验收和证据含义

第一批工作围绕 `autonomy_checks.py`、共享严格 JSON 解析器、验收回执和用户可见指标：

1. 为主 `json_equals` 采用明确、版本化的严格语义。新增重复键、无关/目标字段非有限值、溢出数、布尔/整数、整数/浮点、嵌套深度与最大文件的负例/边界用例；旧回执保留原 check version，不改历史结果。
2. 明确深度计算：业务数据、请求封装和回执封装分别受限。避免重演 v0.8 中有效 depth=32 数据因传输层额外深度被拒绝的问题；不能为一个入口宽放所有解析器。
3. 决定 paused 对发布的语义，选择“冻结发布”或“已接纳的安全结算允许完成”，随后用竞争时序钉住该含义；未知结果仍保留候选。当前研究没有预设一个尚未批准实现的竞态补丁。
4. 自我模型将 availability、实际排序值、样本数、作用域和统计不确定性明确分开。既有校准数据仍有效；不能以新字段重写旧预测。

验收：原最小复现得到明确拒绝或 unknown；合法精确类型样本继续成立；有历史 check version 的账本可恢复；已验证输入/原生回放仍通过。该阶段应有独立 RED→GREEN 回归和正常 CI。

### R1：可恢复的完整工作流

新增独立步骤计划与效果账本，不在现有 `goals.state` 内堆叠所有细节。冻结 `plan_hash`、依赖 DAG、步骤输入/检查器/能力和稳定 `operation_id`。执行尝试 ID 与传输重试 key 分开；步骤从 pending、admitted、running、verifying 到 succeeded/failed/unknown，恢复先对账再行动。局部重规划生成新 plan revision，保留旧承诺和已发生效果。

外部适配器须声明是否支持稳定幂等 key、同 key 变意图冲突、结果查询、fencing、补偿以及保留期限。提交前检查与效果发生之间的竞态只能由实际效果端协议处理；无法做到的动作不获得 exactly-once 标签。补偿是新的、也可能失败的动作，不假装撤销时间。

验收：至少三步依赖任务，在远端提交后丢回复、任意相邻持久化边界崩溃、租约交接、工具暂时不可用、计划漂移和补偿失败时，均保留准确的步骤/效果收据。报告完整成功、局部成功、未知、重复效果、成本和人工干预分母。先离线故障枚举，再真实适配器影子运行和有界长时间 soak。

### R2：受限、可证伪的根因诊断

独立诊断账本引用原 observation，保存被检验假设、允许改变的因子、原失败签名、控制/干预/负对照、输入/程序/环境/检查器 hash。等级包括 observation、hypothesis、intervention_supported_cause、refuted 和 inconclusive；模型只提出假设，可信程序依据收据升级。

第一批干预仅覆盖可撤销、可重放任务。先确认同类失败可复现，再缩减和干预；未知、阴性对照异常、范围漂移或清理未知均不发布原因。允许多个原因和最小修复集，不强填唯一根因。

验收：本轮两个注入故障在产品诊断入口中得到有界、多原因证据；无轨迹旧失败为 unavailable；联合故障不会被单点修复失败误判为无关。诊断与模型调用预算分别持久计数，重启不重复消费或发布旧结论。

### R3：冻结机制的真实因果评测

先建立独立评测 harness：生成关闭、候选版本冻结，经验检索/技能可用性/自我模型反馈分别可控。每对试验在相同逻辑 source/contract/执行身份下从等价隔离快照开始，随机 B,T 或 T,B 顺序；执行后确认静止与清理才恢复下一份副本。端口/profile 的物理隔离与逻辑身份保持需明确证明，不能伪造身份连续性来搬运旧能力。

预注册任务清单 hash、机制 hash、分配、唯一主要结果、难度分层、样本数、停止规则、失败/未知处理、预算和最小有意义收益。主要结果是分配后在期限内完成且清理确认的比例；策略退出、超时和失败仍留在分母。报告原始差值及区间、成本、首次/累计成功，不挑表现好的子集。

对固定答案可能被短路的契约，事先限定结论为契约成功；算法/技能执行研究另行建立可信动态 oracle 与执行绑定。预注册主效应区间不能由挑选一个更有利的检验替代；exact 配对检验的对称 null 与任意异质任务下的平均效应为零需要区分。

样本量由预期效应、配对相关性、任务族聚类和资源上限推导；384 是本轮模拟配置，不能直接宣布为真实模型足够。固定 N 不反复窥探显著性；需连续监测时改用已预注册的 sequential 方法。留出集保持不参与策略生成，发布后才看成绩；版本搜索使用独立确认集。

验收：先证明 B/T 唯一差异确是目标机制，scope 资格相同、没有组间污染。随后按预算开展真实调用；只有对应试验结果支持时，才宣称该机制对所测任务分布有因果收益。主观意识和通用能力不属于此统计结论。

### R4：功能元认知与意识理论研究

分别研究预测校准、错误排序、监控后是否选择复核/弃答/换计划，以及这些选择的成本和最终成功。预注册监控正常、监控遮蔽、监控扰乱、成本匹配控制等条件；有独立结果后比较行为。把“能陈述自己的状态”与“状态信息真正改变控制”分别计分。

对 GNW、HOT、RPT、AST、IIT 的指标，逐项列出所需内部证据和可观察程度。闭源 API 不提供内部激活/因果结构时，对依赖这些数据的指标写 unmeasurable；提示词、模块名、控制器循环和自述不能替代模型内部证据。可以先检验系统级的信息广播、监控反馈和注意控制，但须称为这些**功能性质**。

意识理论之间存在分歧；已复核的 2025 对抗合作研究挑战了两种理论的部分预注册预测，并没有给人工智能发放意识认证。下一阶段可增加理论支持、反证与不可测记录，保留与功能性能不同的结论。无需等意识争议解决才继续做自主工程。

### R5：有限正确性论证

选择一个小而关键的状态机：接纳/恢复/unknown/发布/退役，以及 pause 与范围漂移的次序。定义安全不变量和在何种公平性/可用性假设下的活性；把外部效果端当作明确建模的参与者，不隐藏在“函数返回成功”里。

用有限模型检查寻找反例，再把状态转移与 SQLite/宿主接口对应；差分/性质/故障注入测试检查实现是否符合模型。为受限候选程序采用输入类型、资源界和独立参考函数；证明携带明确假设和版本，不用一个 pass 标签覆盖全部软件。

停机与 Rice 类结果限制的是任意程序的通用判定器，并不阻止证明某个受限程序或特定不变量。完整自然语言任务、永久变化的外部世界和所有可能程序不能由当前有限测试保证普遍正确。该研究目标是持续扩大有依据的保证范围，并准确保留未覆盖区域。

## 4. 交付边界

本轮实验没有新增保险库读取、付费 API 调用或生产扰动；模型选择继续沿用已配置的 `deepseek / deepseek-flash`，并未核验底层 V4.1 型号。所有数值按真实产品代码探针、协议夹具或模拟数据明确标记。

R0–R5 是下一阶段的研究/工程门槛；尚未作为产品机制实现。正式工程应将每个阶段拆为独立规格、实施计划、RED→GREEN 回归、独立审查和 PR，继续执行用户已授权的交付流程。研究结论与当前 v0.8 已运行能力分别记账。
