## 1. 当前证据与缺口

阅读 `experience_store.py`、`experience.py`、`skill_store.py`、`skill_learning.py`、`skill_replay.py`、`autonomy.py`、`self_model.py` 和 v0.8 原生报告后：

- 经验策略在两个不同新目标的首次机械成功后可以激活；“heldout”在这里是账本中目标不同、时间较后、首次成功的规则，没有随机未使用策略的对照。策略被选择、适用任务难度、模型版本、时间、成本和重试均可能混杂。
- 技能在有限可信用例和原目标字段条件通过后发布；这是该版本在这些输入上的认证。原例由失败后选择，回放成功不能识别收益相对于“不提供技能”的反事实。
- v0.8 报告记录四个 case、一次原生运行成功、程序/规范输入 SHA 和清理凭据；报告自身也明确排除因果提升。任务主执行记录 56,948 tokens，另有三次辅助预算调用，不能把主执行 token 数当作整轮训练与执行总成本。
- 自我模型的历史结果影响规划输入和 `rank_ready()` 任务顺序。若处理组多选容易任务，已完成任务成功率上升可能只是选择改变；必须保留所有事先规定的机会任务作为分母，另测选择/排序的净收益。

当前合理表述是“有限认证”“某次观察到执行”“特定条件下复用关联”。没有随机基线时，报告不应写“学习导致成功率提升”“反思修复了该失败”或“更有意识”。

## 3. 先定义三个不同估计量

1. **冻结复用效应**：在固定 scope、同样新任务分布、同样执行器和资源上限下，提供一个已经训练/认证的技能，相对不提供该技能，机械成功率差 `Δ = E[Y(skill available)] − E[Y(skill unavailable)]`。这是首先可做的有限实验；训练成本另报和摊销。
2. **持续学习政策效应**：每个独立 episode 从相同空白状态出发，随机允许/不允许训练和复用，对整个“失败→学习→后续任务”序列的总成功、成本和恢复作比较。实验单位是 episode，不能把共享同一个学习状态的十个后续任务算十个独立样本。
3. **自我模型政策效应**：随机给予/屏蔽历史能力估计，保持任务承诺、预算、许可和验收机制相同；在固定机会任务队列内比较单位预算完成量、延迟、漏选任务和校准。这里的收益来自选择与排序政策，和单任务执行成功率不同。Brier/calibration 改善也不是任务收益的替代终点。

整体“全框架 vs 不用机制”的比较可另立一个主实验，结果只能归因于组合干预。要拆分经验、技能、自我模型贡献，另用单项消融或2×2×2 factorial；交互项也要预先规定，不能把组合收益全归给一个机制。首次避免同时做八组昂贵试验。

## 4. 仓库中的三个实验资格门槛

**开关门槛。** `learning_enabled=false` 同时屏蔽经验和技能的学习/检索，不屏蔽自我模型的规划/排序影响。因此它只能定义一个组合干预，不能充当“仅关闭技能”或“关闭所有机制”的消融。单项试验需要评测适配器/明确开关，并保存实际请求里哪些绑定存在的 receipt；不能只看配置名称。

**scope 门槛。** 经验/技能绑定 `source_id`、完整 `contract_hash` 和 `execution_identity`，技能还绑定任务/清单 digest。完整合同包含验收路径和期待值；identity 包含 API URL/profile 等。把两组改用不同 profile、端口、路径或验收值，再复制数据库的学习版本，会使版本资格改变。如此比较可能测到“资格不匹配”，而非技能无效。

首轮仅使用相同逻辑路径、source/contract/identity 的隔离快照，在各次执行前恢复状态、清除会话及产物，并用新 session ID。恢复必须覆盖输入/DB/文件/执行器会话/待结算提交/残留 worker，而不只是删除输出文件。每次在 admission 前证明两组具有同一 scope，只有预注册的检索可用性差异。若环境无法保持身份和隔离，就先做评测适配工程；不要手工改不可变作用域行规避校验。跨 scope 迁移需单独设计可信导入和重新认证。

**泛化门槛。** 现有 sum 技能 scope 的期待值固定为6。可在相同合同下测试不同且未训练过的整数列表、顺序、元数据和列表长度，但这种实验只支持固定 scope 下的新输入，不能推广到任意总和、任意代码任务或研究/个人任务。训练例、技能 holdout、原例回归都不能再充当最终确认集。更多函数族需要各自的完整固定合同，且按家族留出；新 scope 的能力尚需实现和单独评测。

## 5. 可直接实施的有限预注册 protocol P1

下列是准备执行的规格，不声称本研究已经运行真实模型实验。

**对象与资格。** 选择一个通过 scope 门槛的确定性 JSON 任务族。由独立生成器产生新输入，冻结规范输入、验收器、环境镜像/代码/清单/训练版本和任务列表 SHA。事先按长度/结构复杂度/边界值形成易难层；难度不得用确认集的运行结果重新分组。固定逻辑验收值时，生成器必须排除固定答案短路；除现有字段条件，还需研究用完整输出或未公开可执行条件，且两组完全相同。若模型只要写 `sum=6` 即可过字段验收，就不能把高成功率解释为“正确计算”或技能执行；真实任务计算结论需要额外执行/算法检查。

**两组干预。** B 与 T 共用同一 pin 的模型/provider、提示词基础、温度、工具、输入、权限、验收和最大重试/调用预算。T 可收到被冻结的技能绑定；B 收到同样业务输入但无该技能。关闭双方评测期间新增学习；每一任务对从训练结束后的同一快照恢复，防止首个失败造成技能退休后影响后续样本。已训练策略和自我模型如何处理必须写入 manifest：首轮保持两组相同，不能连同技能一起变化。B 本来就有 Python/terminal 工具，不因不提供技能而禁用本有能力。

**分配和顺序。** 每个任务输入各做一次 B/T，随机决定两个隔离执行槽的处理身份和执行顺序，按预定难度层和小时间块平衡。相邻运行减少 provider 时间漂移。克隆任务是匹配实验，不代表能够重放同一个模型抽样噪声；若 provider 不支持有效 seed，就记录不支持，不能伪称 identical seed。只有隔离和无 carryover 已验证时才采用 AB/BA；否则改用并行独立环境的配对分配，或家族/episode 层随机化。

**防污染。** 测试生成器和验收期待不交给学习程序；确认集不用于改代码/提示词/任务选择。用于调参的 pilot 集单独冻结并永久排除；同一来源模板、同一原例的扰动按家族聚类，不能伪装为独立任务。记录是否公开 benchmark、有可能 pretraining 污染、是否提供示例/答案和确认集被访问。测试答案是固定值6时不能声称这些答案“隐秘”，需要明确答案可猜的限制。

**主终点与分母。** 单一主终点 `Y=1`：在预定 deadline/重试上限内通过独立业务验收，满足预注册执行要求，且结算/清理确认。未知、超时、预算耗尽、格式/动作无效、执行失败、清理不明、没有被调度的机会任务都按该终点失败，另保留原分类。所有事前分配的任务必须进入 intention-to-treat 分母；不得只保留“已执行技能”“有 receipt”或“两组都没超时”的样本。预注册的全局基础设施故障可以触发整块暂停/不作确认结论，不能看到处理结果后把单组失败剔除或补跑到成功。

**资源与副终点。** 同样 run/call/token/deadline 上限，真实花费可以不同；报告总成本而非强行假设相同。每个分配 run 记录主执行、规划、策略/技能合成、评测计算、重试、缓存命中、账单 token/金额、墙钟时间及失败类别。报告每次分配的成本、总成本/独立成功数、延迟和难度层结果；不能只比较成功运行的低延迟。冻结复用实验报告训练一次性成本及 `C_train + N*C_reuse` 的摊销曲线；完整学习实验把训练失败和训练预算也算进去。以预定资源上限的简单 baseline 重试策略作后续次要对照，检验是否只来自多采样。

**分析。** 主指标是配对绝对成功率差，单位 percentage points，附两组成功率、discordant 2×2 表、区间和样本数。独立二元任务对可以使用预注册的 exact paired binomial/McNemar 检验；其有效性依赖独立任务对和配对可交换性，不解决污染或依赖。精确条件检验的对称无效/随机化 sharp-null 不能未经证明就等同于任意异质任务下的“平均效应为零”；若任务固定且效应异质，需以预注册平均效应区间或经验证的分层/家族随机化分析为主，保留 exact 检验的明确 null 范围。区间采用按预定义层、保持配对、按家族/episode 整体重采样的 bootstrap，并说明是近似区间；重复 seed 在家族内，不把它们展平当新任务。另报各层和性能分布。对少量强依赖家族，应进行家族层随机化/置换并扩大独立家族数，不能仅提高 seed 数。零分歧和小样本要用边界保守方法，不能让 bootstrap 零宽区间变成确定性能力保证。

**多重比较与停止。** 只有一个确认主对比和一个主终点，固定 N，不做见好即停。经验/自我模型/多个技能、难度层、成本与准确率等次要比较先标探索。若必须宣称多个确认收益，预先定义检验 family，使用简单 Bonferroni 或完整实施 Holm 程序控制 family-wise error，并增加样本预算；不能只公布显著的一项。预注册安全/资源停止发生时保留全部记录并输出“未完成/无确认结论”。以后采用 S3 的序贯设计，需要新的预注册和独立验证，不以普通 CI 反复查看。

**发布规则。** 在完整协议与资格审计通过、区间/效应/成本都公开后，可以写“在该固定 scope、任务分布、模型版本和资源上限下，随机提供该冻结技能的平均成功率差为 X pp”。设计中的最小值得检测差10 pp是规划参数：在真实差10 pp时有能力排除零，不代表证明提升至少10 pp。若 CI 包含零，写“未证实收益”；若为负，保留负结果。结果不能自动扩展为持续学习效应、意识、一般正确性或个体根因。

## 6. 样本量和资源建议

首轮先做 **12个独立任务对的工程 pilot**，检查隔离、scope、分配、执行证据、超时和所有成本字段；这24次 run不是充分的提升证据，也不并入确认集。用户现有默认 `daily_runs=8` 若实际沿用，至少3天，仅提高并发并不免除 profile 总预算约束。

独立二元配对下，设 `q=P(B!=T)`、希望在真实 `δ=0.10` 时以双侧 α=.05、power≈.80 检测相对零的差异。保守近似 `N ≈ ceil((1.959964+.841621)^2 * q / δ^2)`，以下为**独立任务对**，不是单个 run：

| 规划 q | 约需任务对 | 两组主执行 run |
|---|---:|---:|
| .25 | 197 | 394 |
| .40 | 314 | 628 |
| .50 | 393 | 786 |
| 1.00 最坏范围 | 785 | 1,570 |

这里用了忽略 `δ²` 的保守方差近似，没有声称 exact power。q=.5不是无条件最大值，不能随意把393对称作对所有任务都有80% power。12对 pilot 对 q 的估计很不稳定；若资源有限预定393对，应声明依赖 q≤.5 的规划假设，独立验证并做功效敏感性；若需接近最坏情形保障可选785对，再用预注册精确/蒙特卡洛计算修正。检测5 pp约需四倍样本。重复 seed、同一模板/episode 的关联会降低有效样本量；先用设计效应/家族层模拟修正，不能把表中的独立数量直接套到相关运行。

按393对、每次 run 规划主+辅助24k tokens计，约18.864M tokens；这只是**规划情景**，非费用承诺或当前实现的账单硬上限。v0.8 原生报告单次主执行已经达到56,948 tokens，且辅助另算；调度估算/超时取消可能仍有迟到计费。正式实验先测实际全量账单和 provider 单价，再定固定预算；不得为达样本量绕过默认8 runs/day、技能评测16/day或现有额度。按8 runs/day完成786次主执行至少99天，还未计训练/故障/辅助约束。可以缩小首个研究问题或等待累积，不能用低样本替代证据，也不自动开展付费运行。

持续学习/自我模型比较采用独立 episode 作为单位，需要依据 pilot 的 episode 间方差重新计算；上述二元 task-pair 表不可直接复用。

## 8. 证据等级和下一步

这是为本项目定义的证据层级，不冒充通用学术标准：

| 等级 | 可以支持 | 当前情况 |
|---|---|---|
| E0 | 分析/协议工具在模拟或解析夹具上可运行 | 本次演示；无实际 agent 增益 |
| E1 | 有限独立测试/执行证据和适用边界 | 现有v0.8认证与原生 smoke |
| E2 | 观察性复用关联和时间后续样本 | 现有经验激活逻辑；无随机收益 |
| E3 | 单一预注册随机实验范围内平均处理效应 | 尚未运行；需要P1及资格审计 |
| E4 | 独立复现、跨任务家族/时间、实际成本与故障检验 | 尚缺；不能由增大同例 seed 替代 |

建议后续工程顺序：独立评测 manifest/分配与不可变 receipt → 完整成本和所有机会任务记录 → 分别控制经验/技能/自我模型的可信消融适配器 → 同 scope 状态恢复和非付费隔离测试 → 12对工程 pilot → 固定 N 确认实验 → 按原协议完整公开负/正结果。现有上线/技能激活标准和研究结论判定应分开；未证明因果收益不等于技能不能用。

所有平均处理效应结论仍不回答“某次失败内部为什么发生”，也不证明主观意识或所有未来任务的正确性。那些研究需要单独可证伪的理论指标、干预和边界。

## 9. 交付文件与字段

建议复制到仓库研究目录：本报告、`source-index.json`、探针脚本 `probe_sources.py`/`second_sources.py`、其输出 `source-probes.json`/`second-probes.json`/`book-probe.json`、演示脚本 `offline_demo.py`、`offline-protocol.json`、`offline-analysis.json`。`build_source_index.py` 可一并保留用于重建索引；它依赖上述probe输出。`extract_sources.py` 是本次正文提取辅助，不属于产品。不要提交下载的 HTML/PDF/TXT 正文缓存或全文。

索引顶层：`schema` 是索引版本；`study_date`、`repository_revision` 为研究基线；`network_and_credentials` 为获取边界；`sources` 是真正取得并读过方法的七项；`non_sources` 明确排除挑战/重定向/超大下载。

每个source：`id` 是S1–S7；`authors/title/publication/primary_url` 为书目；`requested_full_text_url/retrieved_full_text_url` 区分原请求和重定向终点；`http_status/content_type/bytes/sha256` 是获取事实及字节绑定；`scratch_cache_file` 仅指本次scratch全文缓存，不承诺未来环境存在；`read_sections` 是实际阅读范围；`protocol_application` 和 `transfer_limit` 区分迁移出的工程建议与论文没有证明的内容。探针输出中的 `error/response_excerpt` 保存访问失败原因，不是正文证据。

评测边界裁定：首轮冻结复用而非在线更新，代价是不能评价持续学习；固定同 scope 而非跨域迁移，代价是结论范围窄；单一固定 N 主终点，代价是需等完整样本及足够资源；全量失败入分母，代价是成功率可能较漂亮日志下降但更接近真实运营；完整成本而非主执行token代理，代价是需补齐辅助与迟到计费观测。
