## Strengths

- Observation revision binds both input content and projection rule; goal creation stores the original selected observation rather than reconstructing it from the second source read. The second observation is used to reject drift.
- `BEGIN IMMEDIATE` covers goal insertion, payload quota calculation, and snapshot insertion. Quota failure rolls back the goal; duplicate creation neither adds a snapshot nor charges payload twice. Old goals cannot silently acquire new snapshots.
- Dispatch checks the current rule and exact canonical request binding before attempts/run budgets. Reconciliation of an existing unsettled submission returns its original request before those new-admission checks.
- Replay uses the frozen contract and request-bound snapshot. Same-input cases retain full-output comparison and add the field predicate; contradictory base answers prevent generation. Canonical comparison preserves boolean/integer/float distinctions.
- Publication independently rebuilds the plan inside the write transaction and checks current manifests/input rules, origin, digest, every case, code identity, and cleanup. Pauses and unknown evaluations retain already-paid code.
- Planner and synthesis use explicit allowlists. Public goals now omit request contents and payload; self-model exports do not expand the new snapshot. The documented temporary facts exposure and metadata hashes remain explicit.
- The fixed native runner executes the same program bytes and feeds the same input bytes whose hashes it checked. Evidence maps the frozen request through native run/session/tool call/result and checks exact canonical output. Documentation correctly separates original-regression input from the later live goal input and discloses the synthetic failure fixture and forced shutdown.

### Important — I1: valid depth-31/32 snapshots cannot pass request-envelope validation

**Locations:** `task_inputs.py:108` (primary); the same request parsing pattern at `skill_replay.py:25` and `scripts/skill_smoke_evidence.py:52`. The related native result-envelope occurrence is `scripts/skill_smoke_evidence.py:79`. `skill_evaluator.py:27-46` supplies the fixed default depth limit.

**Trigger:** authorize `observations`, set its value to 30 or 31 nested lists around the scalar `0`, and run a normal Controller tick. The source/projection has depth 31 or 32 and is only a small number of bytes. `observe_sources` and immutable snapshot validation both accept it. The Controller then wraps the data as `intent.task_input.data`. `valid_binding` calls `strict_json` on that entire envelope with the same limit of 32, adding two levels to the user's allowed depth and rejecting the identical frozen binding.

Independent end-to-end reproduction using the existing `TaskInputTests` fixture and real Controller/SQLite paths produced:

| List nesting under observations | Source depth | Observation | Accepted goals | New dispatches | Result |
| --- | --- | --- | --- | --- | --- |
| 29 | 30 | available | 1 | 1 | running |
| 30 | 31 | available | 1 | 0 | blocked: input_snapshot_no_longer_applicable |
| 31 | 32 | available | 1 | 0 | blocked: input_snapshot_no_longer_applicable |
| 32 | 33 | unavailable | 0 | 0 | no goal |

A direct request with the depth-32 snapshot was only 1,191 UTF-8 bytes, so the request byte limit was not responsible. `_validated(snapshot)` succeeded, but independently invoking the replay builder with an otherwise matching goal/submission returned `replay_unavailable`; invoking the native audit with the same valid snapshot/request returned `native_input_binding_mismatch` before native DB lookup. These two consumers must be fixed with admission, otherwise an admission-only repair merely moves the failure downstream.

The related result-envelope reproduction is also real: `strict_json(canonical(value))` accepts a value consisting of 32 nested lists, while a correctly mapped synthetic native terminal receipt containing `{"code_hash": ..., "value": value}` is rejected by the audit as `native_skill_execution_unverified`. The added receipt wrapper consumes another depth level.

**Implication:** a documented, successfully accepted input shape consumes planning work and permanent snapshot quota but can never dispatch. Its failure reason incorrectly reports an applicability change despite unchanged data/rules. Replay/native audit have the same mismatch. This violates the advertised depth-32 boundary and needs a test-backed fix before merge.

**Fix direction:** distinguish bounded transport-envelope parsing from the depth-32 business JSON validation. Preserve strict duplicate-key and nonfinite rejection, keep source/projected data and candidate stdout limited to 32, and permit the known enclosing request/receipt levels when parsing transport objects. Apply the same policy to all three request readers and the native output receipt; avoid globally relaxing source/candidate limits. Add boundary coverage for accepted source depths 31/32, rejected depth33, matching frozen replay/audit, and strict rejection behavior after the change. The manifest's own whole-object normalization already imposed wrapper depth at BASE; it is inherited behavior, not a separate new v0.8 finding.
