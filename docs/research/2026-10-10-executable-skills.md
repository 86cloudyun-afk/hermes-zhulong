# 独立可执行技能工程依据

本次从已合并 v0.6 `830d960` 出发，对固定原生 Hermes `73162b0` 的 Runs 请求、技能预处理、Docker 挂载、会话存储和原有自主账本做了两项独立只读审计。关注的是可验证的执行能力与恢复，不以“自主意识”叙述替代验收。

Reflexion（2303.11366v4）的方法是语言反馈记忆，不能直接认证新程序正确；Voyager（2305.16291v2）的可执行程序技能库和执行反馈给出了候选→验收→复用的参考。本次审计重读了已有下载的论文原文相关章节，并沿用 [v0.6 跨学科研究](2026-10-10-evidence-learning.md) 的心理学、元认知和工程学结论；没有复现论文基准，也没有声称覆盖全部最新研究。

工程选择如下：

- 程序和期待答案分离。候选只看到一个 JSON 输入；控制面比较输出；退出码、自报“passed”或自然语言解释不能发布版本。
- 留出案例从不进合成请求、工具状态或普通自我模型。每个案例在新容器运行，清单/身份/完整契约绑定版本。固定案例通过只代表有限测试，不是通用正确性。
- 采用私有 SQLite 保存不可变代码，随 Runs input 冻结。原生 API 接受原始字符串；无需改变固定 host，也无需打开 skill_manage 或 inline_shell。原生 skills 空 RO 和 worker 所有挂载限制保持。
- 发布、替换、退役和回退由可信事务处理。旧请求保留原内容；旧版本迟到失败不能影响新 active。绑定只是“提供给任务”，不证明运行或因果收益。
- 跨进程 flock 贯穿认领、Docker 操作和结算；客户端继承锁并有独立超时。每日评测预留和共享模型预算限制重试，清理不明禁止晋升及后续评测。

两个独立审计明确指出旧账本未保存失败时业务输入。因此本版只评测可信清单的回归和未公开例，不把任意旧失败称为精确回放。真实 native smoke 使用明确标注的无输出执行夹具触发学习，然后额外审查持久 terminal 调用、对应结果、代码 hash 和机械产物；不把夹具称为真实 provider 故障。

详见 [规格](../superpowers/specs/2026-10-10-executable-skills-design.md) 和 [实施计划](../superpowers/plans/2026-10-10-executable-skills.md)。后续仍需不可变失败输入、步骤依赖与重规划、实际外部连接器、磁盘配额和长时运行研究，最后才到独立内核发布与回滚。
