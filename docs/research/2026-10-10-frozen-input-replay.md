# 冻结任务输入与原目标字段回归（v0.8）

v0.7 的生成、独立评测和版本恢复仍有一个具体缺口：失败账本没有业务输入。用当前源补读可能得到另一版本，单记 hash 又不能恢复原数据。因此本轮选择同一次严格观察取得授权投影，在形成目标的同一 SQLite 写事务冻结。设计和权衡见[规格](../superpowers/specs/2026-10-10-frozen-input-replay-design.md)及[计划](../superpowers/plans/2026-10-10-frozen-input-replay.md)。

依据沿用上一轮[跨学科研究](2026-10-10-executable-skills.md)：测试驱动的程序改进需要独立可执行反馈；自我模型、失败凭据和验收必须保持区别。本轮是这些原则的工程延伸，没有新增主观意识或心理测量实验，也没有声称重新验证全部学科论文。

默认没有输入捕获。可信 `persist_input_fields` 是临时 `input_fields` 的子集；规范投影上限 4096 字节、深度32，累计 payload 默认8 MiB。只存选中业务字段，不复制整个源、聊天、工具正文或保险库凭据。规则和数据共同进入观察 revision。两连接争最后额度时，事务保证失败不留下孤立目标；已有未知执行在规则移除或额度关闭后仍保留原提交对账。普通工具/命令和自我模型只导出 hash/大小。

`replay_origin` 从不可变目标/提交构建私有评测计划，程序合成不收到原输入或新期待条件。基础输入相同则复用 case 并保持完整输出比对；不同最多追加一个字段回归 case。清单期待与原条件矛盾记录 `spec_conflict`；缺快照记录 `replay_unavailable`，均不花生成预算。发布在同一事务重新核对当前规则/清单、原提交和计划 digest。此回归仅覆盖 JSON 字段后置条件，不复现路径、require_change、副作用或失败根因。

旧原生审计使用普通 JSON 和 Python `==`，会混淆 true/1、6/6.0 并忽略重复键。针对这些错误的拒绝测试先观察到失败，本轮改为严格解析与 canonical 比较。固定 smoke runner 核验程序/规范输入 SHA，并执行读取一次的同一份程序和输入字节。原例输入与真实新目标输入分别记录，有限审计不等于所有日常执行的强制认证。

验证记录在整轮测试、有限真实模型运行和独立审查完成后补入[交付证据](2026-10-10-v0.8-validation.md)。不承诺长期无人运行、主观意识、通用正确性或因果提升；后续仍需任务依赖/重规划、外部事务、磁盘硬配额、长时故障与成本观测、控制内核独立发布回滚。
