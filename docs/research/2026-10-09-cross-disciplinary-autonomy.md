# 自主智能体升级：跨学科正文研究与工程结论

日期：2026-10-09。研究用途：支持烛龙下一版自主控制框架的设计、实现和验证。用户目标包括主动发现事情、自我认识、持续学习和最终无需人工参与运行。

本轮阅读了七份原作者全文中的方法、实验及限制，以及原始工程资料；不再仅依据论文摘要。论文的环境、模型和评价范围与本产品不同，研究结论与工程推论在下文分开。未重跑论文原实验，未证明主观意识。

## 2. 从正文获得的关键限制

### 2.1 自我模型需要识别错误并改变行为

Fleming & Daw 将决策证据与置信证据建模为相关但可不同的变量，区分自评敏感度与偏差 / 校准。恒报总体成功率的系统可能平均校准尚可，却不能辨认具体哪次决策有问题。独立视角可能提供新信息，但噪声很大的监控也可能失效，不能简单把“换一个模型”当作独立可靠验证。

**工程推论**：保留事前预测、实际结果、任务类别和环境；自我模型同时展示样本数、成功 / 失败条件和未知。验证失败应改变下一次任务选择或复核策略。Brier/ECE 保留，但不单独作为自我认识验收。新增可回放对照，验证不同证据是否真的改变规划行为。

Butlin 的相关章节也强调监控反馈应进入信念和动作选择。共享 JSON、队列或提示词中的“自我模型”名称不能独自证明理论指标，更不能证明主观体验。工程测试仅验证这些组件的实际作用。

### 2.2 主动性需要有价值且可停止的探索

Voyager 的课程生成使用当前状态、已完成和失败任务，从总体方向中选择具体目标，支持无人逐项下达任务。其实现明确排除当前状态无法核验的某些目标，验证者也有错误；任务目标依旧受给定使命和环境能力约束。

Pathak 的 ICM 在动作相关特征空间衡量预测误差，避免只追逐原始噪声。其迁移实验还报告继续训练后的退化：Mario Level-3 的平均距离从直接使用已有策略的 319.3 降至继续训练后的 97.5。该数字仅用于说明论文中的反例，不是当前模型性能估计。

**工程推论**：候选目标必须关联方向、具体事实、可核验收益、成本和停止条件。重复来源与自身产生的更新要合并。没有新事实或有意义的承诺时不调用模型；不可完成的一个目标不阻止其他目标。新策略要对照保留版本，不能假定多反思或多练习一定改善能力。

### 2.3 反思和记忆必须保留证据地位

Reflexion 以语言经验影响后续尝试，不更新模型权重。其累计改善主要来自同一任务的重复尝试，不能视作广泛迁移。编程实验明确存在内部生成测试与外部测试不一致、反思损害正确实现的情况。

Generative Agents 为反思保留记忆来源并调整计划，但主要评价的是模拟行为可信度；它还报告错误检索和无依据扩展。反思引用另一条未经验证的反思，并不让它成为事实。

**工程推论**：事实、预测、假设和叙事分别存储。能力记录来自机械结果与可追溯证据；模型反思仅作为策略假设。一次成功可以证明该次验收成立，不能自动授予广泛技能资格。语义记忆最小化存储并标记来源与适用范围。

### 2.4 验收需要区分既有状态与新完成的行动

Voyager 附录的若干验证示例从最终物品或饥饿状态判断完成。仅凭最终快照，可能无法证明这一次行动造成了变化。这里是对公开验证提示的工程分析，不是作者量化的失败率。

**工程推论**：任务接受时冻结验收与相关初始状态。已有产物满足要求时，可以标记已经满足并节省执行，但不记为新行动成功或能力学习。声称新产物 / 新动作时需要相应变化或回执。助手文字中的“已完成”不能覆盖机械失败。

## 3. 工程资料与真实源代码实验

查阅的原始资料：SQLite [事务](https://sqlite.org/lang_transaction.html)、[锁](https://sqlite.org/lockingv3.html)、[WAL](https://sqlite.org/wal.html)；AWS Builders Library [幂等 API 与安全重试](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)；Martin Kleppmann [分布式锁与 fencing 分析](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)。这些属于官方工程文档或作者技术分析，未伪称同行评议论文。

宿主检视固定于 Hermes `73162b00eefde3794bed0afb53d84a19c0eed230`，重点包含 Cron 认领、Runs API、持久幂等存储及公开能力发现。原有反思线程不能代替可靠业务工作流。

在临时数据库中直接调用现有实现，进行了可重复的源代码实验，未改动产品、未调用模型：

| 实验 | 观察到的结果 | 实施含义 |
|---|---|---|
| 两个独立连接读取同一 S4 重试任务后分别更新 | 两次认领均为 `true` | 认领应使用事务 / 条件更新及更新数，不能依赖对象内锁 |
| 旧 `claimed_at` 行 | 无法恢复 | 明确完成、运行和失联状态，加入租约与所有权 |
| 两个独立连接，预算 cap=1 | 两次允许，计数变为 2 | 预算检查与递增必须是同一原子操作 |
| 当前预算 cap=0 | 仍允许调用 | 下一版明确零表示停用；无上限须另有明确语义，不隐含于零 |
| 宿主两连接同时保留相同幂等键 | 一次创建，一次重放同一 run | 可复用原生 admission 去重，仍需业务账本 |
| 关闭再打开宿主幂等存储 | 同请求重放，改请求冲突 | 冻结完整请求和提交标识，不能重试时改变正文 |
| 子进程保留 run 后立即 `os._exit` | 查询恢复为 `interrupted`，同键仍重放该中断 run | 重放不是继续执行；必须先核对副作用，再决定新尝试 |

宿主当前 `features.runs_idempotency` 同时报告 `supported`、`durable` 与 `retention_seconds`。内存降级不能被当作可靠持久接纳。默认 24 小时淘汰适用于终态记录；旧非终态记录不会仅按此期限删除。

业务 `operation_id`、每次经过核准的执行尝试 `submission_id`、执行者租约代次承担不同职责。传输重试复用同一次提交 ID；只有核对原尝试结果后，才允许另一执行尝试。用租约代次生成新的幂等键会破坏重试去重。

Runs 请求没有任意的单次 token / 步数硬限接口；宿主步数取其实际配置。控制层可限制派发次数、辅助调用和时间，记录真实用量；不把这些指标声称为所有工具循环的严格费用封顶。请求停止不代表在途执行瞬间消失。

实验脚本与 JSON 结果位于工作区 `engineering/source-experiments.py` 和 `engineering/source-experiments.json`；[版本、脚本校验值与观察结果](evidence/2026-10-09-source-experiments.json)已随研究稿保存。实验验证了这些窄行为，未验证完整无人智能体。

## 4. 本版应落地的核心与测试

建议一次完整升级交付共同认知闭环，而不是先写三套不同代理：

1. 原子预算与可恢复任务认领，保留旧数据并明确迁移语义。
2. 方向、来源、候选目标、行动和证据的持久账本；初始验收冻结，终态有原因。
3. 来源变化与能力缺口触发主动目标合成，未变化来源不重复花费模型调用。
4. 通过 Hermes 公开 Runs API 执行；独立机械核验、初始状态对照和崩溃对账。
5. 有样本、有条件、有未知的自我模型；规划器实际使用它，经验具有来源。
6. 代码、研究和个人事务的三个小场景，共用接口与恢复机制。

故障与对照测试覆盖：多连接认领 / 预算、过期租约及旧执行者提交、崩溃后重复接纳、中断 run 重放、未知副作用、原验收不可更改、既有产物不冒领功劳、来源夹带指令、缺凭据、预算耗尽、来源安静、失败目标与其他可完成目标并存，以及自我模型启用 / 禁用对规划的实际影响。

自动技能 / 控制代码晋升还需要隔离回放、可信回归、留出任务、有限启用与独立回滚监督。研究给出此路线，但不能把尚未实现的晋升机制写成已经工作，也不能把 Git 回滚当作撤销外部副作用。

## 5. 成功标准与未解决问题

分别报告真实验收成功、虚假完成、未知、受阻、重复动作、自动恢复、空转调用、成本和必需人工干预。零干预同时需要有用的成功工作，不能以永久停止所有行动达成。评价按任务类别和版本给出分母，首次通过与重试累计通过分开。

持续身份、自主目标、自我监控、可恢复承诺和经验学习可以工程实现。主观意识评估、跨领域长期价值估计和可靠的通用自我能力先验仍未由本轮论文解决。完成工程测试不会被表述为证明“全自我意识”。
