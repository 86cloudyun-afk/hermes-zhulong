## Important I1 — Planner capability context is not restricted to the current execution identity

**References:** `autonomy.py:136-141`, `autonomy.py:35-41`; context construction in `self_model.py:95-101`. Design behavior contract §7 requires the planner to receive capability context corresponding to its execution identity.

**Trigger:** Finish work using execution identity A, then change `api_identity_version` (or another execution identity field) to B and discover a new source revision. `_synthesize` copies the complete stored self-model and replaces only its `experience` field. `LLMPlanner.plan` forwards the first 20 capability contexts without filtering by B. Its serialized payload does not separately identify B, so the provider is not even given a reliable selector with which to distinguish its current capability context from historical A.

**Observed reproduction:** Using `AutonomyTests` in a temporary directory, completed one goal under `test-v1`, rebuilt the controller with `api_identity_version='new-v2'`, changed the facts, and captured the actual model argument passed by `_synthesize` to the planner. The current identity was `new-v2`; the sole forwarded capability context was `test-v1` (`old_identity_forwarded=true`). This was not a fabricated malformed snapshot. It followed the normal controller/model lifecycle. Inspection of the native LLM planner confirms that same context is serialized.

**Consequence:** Planning for a new execution identity is informed by an unrelated identity's capability history, contrary to the explicitly scoped planning contract. Merely labeling entries is insufficient when the current selector is absent. With more than 20 historical contexts, slicing also lets unrelated old contexts crowd out the relevant context. Strategy retrieval itself remains correctly scoped; this finding does not claim an incorrect strategy enters an execution request or that capability counters are numerically altered.

**Fix:** Scope the planner-facing capability contexts to `Controller.execution_identity` before applying the context limit. A new identity with no scoped history should get an empty/unknown context rather than silently inherit another identity. Include an explicit current execution identity if the planner requires it, and preserve global historical statistics as clearly identified aggregates rather than presenting them as current-context capability. The public self-model can still retain all contexts.

**Focused regression:** Use two real ledger histories with different identities, switch the controller to the second identity, and capture the actual structured LLM input. Assert all forwarded capability contexts match the current identity; assert the matching context survives more than 20 unrelated historical contexts; assert a new identity gets no historical foreign context. Preserve current scoped strategy retrieval and the unchanged public historical model.

## Minor M1 — Planner strategy retrieval applies a global display limit before scope filtering

**References:** `experience_store.py:190-196`, `experience_store.py:198-204`.

**Trigger:** An applicable strategy is older than 20 newer strategies in other scopes, or newer retired strategies occupy the display window. `planning_context` filters `summary()['strategies']`, but `summary` has already selected only the newest 20 global rows.

**Observed reproduction:** Created one code candidate through normal failure/claim/begin/complete APIs, then 21 newer research candidates. For the original code source/contract/identity, `retrieve(...)` returned one valid strategy while `planning_context(...)` returned zero.

**Consequence:** A relevant strategy disappears from planner context merely because unrelated history grows. Execution retrieval still supplies the strategy, so this is a planning-quality/history correctness issue rather than invalid execution or loss of durable evidence. The same reuse of summary also means planner ordering does not honor retrieval's active-before-candidate preference.

**Fix:** Query eligible scopes directly, filter out retired rows and order active strategies first, then apply the two-item planner limit. Keep the public summary's 20-item display limit independent of selection logic.

**Focused regression:** Preserve an applicable older active/candidate strategy, add more than 20 newer unrelated or retired rows, and assert the applicable strategy remains in bounded planning context. Check active-before-candidate ordering and exclusion of changed source/contract/identity.

## Minor M2 — Stopping the second learning call leaves a permanently pending exhausted job

**References:** `experience.py:41-43`, `experience_store.py:127-132`, `experience_store.py:86-91`.

**Trigger:** The first actual generation attempt fails schema/availability validation. During the second actual generation attempt, pause/stop makes `admissible()` false before the response is accepted. The learner calls `defer`; `defer` writes `state='pending'` with `attempts=2`, null owner and null lease.

**Observed reproduction:** With a temporary real ledger, made the first stubbed structured response invalid, advanced past the retry delay, and had the second response flip admissibility to false. After advancing to time 2000 and running another admissible tick, the persisted row was still `{state: 'pending', attempts: 2, owner: null, lease_until: null}`. `claim` only expires exhausted `claimed`/`generating` rows and only selects `attempts<2`, so this row can never leave pending through normal processing.

**Consequence:** Public job state and durable backlog report an exhausted failure as pending forever, including after restart. This does not permit a third model call and does not mean budget deferrals consume attempts; those protections work. It is a terminal-state/accounting defect on the stopped-response path.

**Fix:** When deferring an owned generating job with an exhausted attempt count, close it in a terminal invalid/exhausted state, or let claim normalize every exhausted nonterminal job. Do not refund already reserved attempts or consume attempts for pre-call budget deferral.

**Focused regression:** Invalid first response, stop/pause during second response, then resume and reconstruct the store from a separate connection. Assert terminal exhaustion, no candidate, no third generation, and no permanently pending row. Retain the existing zero-budget recovery test.

## Review focus assessment

- **Different connections and expired owners:** write transactions use `BEGIN IMMEDIATE`; learning claim ownership uses UUID plus generation and an unexpired lease. `begin`, `complete`, `defer`, and `reject` recheck ownership. Independent-connection concurrency and expired owner rejection tests passed. Two calls can exist across lease expiry, but the old response cannot become the accepted candidate, and generation reservations remain bounded.
- **Unknown/prior artifacts/original retry evidence:** evaluation requires a settled submission, terminal host status, boolean mechanical verdict, matching contract and frozen strategy body/hash/scope. First-pass activation also requires submission attempt 1, goal attempts 1, succeeded state, a different origin goal, and goal creation after candidate creation. Unknown and prior-artifact controller tests, original retry exclusion, preexisting-goal exclusion, and repeated evaluation checks passed. No new denominator inflation was found. The existing first-attempt and eventual-success counters remain separate from strategy use associations.
- **Retirement and idempotency:** new admission checks the binding in the same write transaction as submission reservation. Existing replay uses the immutable submission request and does not validate it as a new binding. Retirement is not reversed by later success. The positive replay fixture covered actual retired state in addition to the passing normal retirement tests.
- **Unavailable learning / budget:** recovery runs before learning, and controller learning exceptions do not cancel reconciliation. Budget exhaustion defers without consuming an attempt; restoration permits later generation. Reserved calls are not refunded after crashes. Final-generation lease expiry is normalized correctly; the stopped-response edge case is M2.
- **Source/contract/execution scope:** execution retrieval, admission binding, and evaluation all compare the machine-constructed full scope. Tests for changed source, domain, contract, and identity passed. Planner strategy filtering uses the same scope but has the history omission in M1. Planner capability context has the separate identity defect in I1.
- **Transactions and immutability:** strategy origin/scope/body/hash/creation fields and learning payload have frozen-field triggers. Frozen submission requests supply use provenance. Evaluation insertion and lifecycle change share a transaction, with a unique strategy/submission key. No external writer interface is added. I did not find a path that rewrites accepted strategy content through the exposed APIs.
- **Bounded contexts:** guidance and request selection are bounded at 600 characters and two strategies; whole execution intents retain the byte cap. Planner contexts/commitments are bounded by counts. Bounds should be applied after relevance filtering, as I1/M1 describe. Generation receives minimal objective/failure metadata rather than full trajectories or source facts.
- **Legacy and disabled learning:** schema initialization is additive and legacy intents without experience remain admissible. The disabled flag prevents new generation and new-request/planner strategy retrieval while existing submissions retain their frozen bindings. Evaluation/sync may still run while learning is disabled; that agrees with the README's narrower statement that disabling stops new generation/retrieval. Default-disabled autonomy returns without doing learning work.
- **Integration:** both new modules are in the installer and protected runtime plugin file manifest. Existing public registration cardinality is unchanged; experience is an added action/read-only state view, not a new model write tool. Startup/storage errors remain guarded so the older observation layer is retained.
